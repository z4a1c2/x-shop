# 电商微信小程序 · 架构设计

## 1. 技术选型

| 层 | 选型 | 理由 |
|----|------|------|
| 小程序框架 | Taro 3 + React + TypeScript | 类型安全、组件化、与当前 IDE 工具链闭环（可编译微信端，保留多端可能） |
| 状态管理 | Zustand | 轻量，覆盖购物车/用户态 |
| 请求层 | Taro.request 封装 + 拦截器 | 统一 token、错误码、重试 |
| 组件库 | NutUI（Taro 版） | 电商组件齐全 |
| 后端 | 微信云开发 CloudBase（云函数 + 云数据库 + 云存储） | 免运维、内置微信鉴权、快速上线 |

## 2. 系统分层架构

```
┌─────────────────────────────────────────┐
│  客户端层：微信小程序（Taro/React）        │
├─────────────────────────────────────────┤
│  接入层：微信云开发 SDK（内置登录态鉴权）    │
├─────────────────────────────────────────┤
│  应用层：云函数（无服务器）                 │
│  商品 · 订单 · 支付 · 会员/用户 · 营销 ·   │
│  库存 · 物流 · 售后                       │
├─────────────────────────────────────────┤
│  数据层：云数据库(文档型) · 云存储(图片)    │
│          云函数定时触发器(超时关单等)       │
├─────────────────────────────────────────┤
│  第三方：微信支付 · 物流快递 · 短信         │
└─────────────────────────────────────────┘
```

## 3. 后端方案（已确定：微信云开发 CloudBase）

| 组成 | 用途 | 说明 |
|------|------|------|
| 云函数 | 业务逻辑 | 商品/订单/支付/会员/营销等，按模块拆分，`wx.cloud.callFunction` 调用 |
| 云数据库 | 数据存储 | 文档型集合（对应下节数据模型），支持索引、聚合、事务、原子更新 |
| 云存储 | 图片/静态资源 | 商品图、轮播图，`fileID` 存储，前端直传 |
| 定时触发器 | 定时任务 | 订单超时自动关闭、优惠券过期等 |
| 数据库触发器 | 数据联动 | 订单状态变更等事件处理（可选） |

**选型理由**：免运维、内置微信鉴权（天然获取 openid）、云函数+云库+云存储一体，最快跑通 MVP 交易闭环；后续规模化如需更强事务/报表能力，再评估迁移自建 NestJS。

## 4. 核心数据模型（ER 概览）

```
user(用户) ─┬─ member_level(会员等级)
            ├─ address(收货地址)
            ├─ user_coupon(用户券)
            └─ points_log(积分流水)
category(分类) ─ product(商品/SPU) ─ product_sku(SKU规格+库存)
cart(购物车) ─ product_sku
order(订单) ─┬─ order_item(订单明细)
             ├─ payment(支付流水)
             ├─ shipment(物流)
             └─ refund(退款单)
coupon(优惠券) ─ user_coupon
```

> 云数据库为文档型，每个实体对应一个集合（collection）；关联关系用 `_id` 引用或内嵌子文档（如订单内嵌 `order_item`）。

## 5. 接口规范（云函数）

小程序端通过 `wx.cloud.callFunction({ name, data })` 调用，云函数返回 `{ code, message, data }`，`code=0` 成功。

| 云函数 | 入参（data） | 说明 |
|--------|-------------|------|
| login | `{ code }` | 登录换取 openid，返回自定义登录态 |
| product | `{ action: 'list' \| 'detail', ... }` | 商品列表/详情（一个云函数内按 action 路由） |
| cart | `{ action: 'add' \| 'update' \| 'remove' \| 'list', ... }` | 购物车增删改查 |
| order | `{ action: 'create' \| 'list' \| 'detail' \| 'cancel', ... }` | 订单创建/列表/详情/取消 |
| pay | `{ orderId }` | 发起微信支付（云函数内统一下单） |
| payCallback | 微信支付回调 | 验签 + 幂等更新订单状态 |
| coupon | `{ action: 'list' \| 'receive', ... }` | 券列表/领券 |
| address | `{ action: 'crud', ... }` | 收货地址管理 |

> 按业务域拆分云函数，域内用 `action` 字段路由，减少函数数量、便于统一鉴权与错误处理。

## 6. 项目目录结构（Taro + 云开发）

```
src/                    # 小程序端
├─ pages/               # 页面：home/category/cart/user/product/order/pay...
├─ components/          # 通用组件
├─ store/               # Zustand 状态
├─ services/            # 云函数调用封装（wx.cloud.callFunction）
├─ hooks/               # 自定义 hooks
├─ utils/               # 工具
└─ app.tsx / app.config.ts

cloudfunctions/         # 云函数（后端）
├─ login/               # 登录
├─ product/             # 商品
├─ cart/                # 购物车
├─ order/               # 订单
├─ pay/                 # 支付
├─ payCallback/         # 支付回调
├─ coupon/              # 优惠券
└─ address/             # 收货地址
```

## 7. 关键架构决策

- **登录态**：云函数 `login` 通过 `cloud.getWXContext()` 获取 openid，返回自定义 token（存于云数据库，含过期时间），小程序端持久化，请求时携带校验
- **库存并发**：下单扣库存用云数据库事务 + 条件更新（`stock >= n` 才扣减），防超卖
- **支付安全**：`payCallback` 内验签 + 幂等（以支付流水号去重），更新订单状态
- **购物车**：未登录存本地，登录后同步云数据库并合并
- **超时关单**：云函数定时触发器扫描超时未支付订单，自动关闭并回补库存
